# Campaigns Module Technical Specification

## 1. Purpose

The Campaigns module is the workspace for planning, communicating, distributing, and measuring civic campaigns and events. It is not a task manager. Its purpose is to help an administrator move from a campaign idea to audience-aware communication, link distribution, event or participation registration, public updates, and performance insight.

The module should connect campaign strategy with real outreach activity. A campaign should not only store information; it should help the team decide what to say, who to reach, how to distribute the message, and how to interpret results.

## 2. Product Principles

1. Campaigns are action-oriented.
   The module should guide the admin toward campaign setup, messaging, audience selection, distribution, and learning from results.

2. Tasks are out of scope.
   Internal work assignment, task boards, and team task management belong in a separate operations layer. Campaigns may show campaign actions and statuses, but should not become a task manager.

3. Communication is central.
   The module should include a communication workspace where teams generate, review, edit, approve, copy, and distribute campaign messages.

4. Audience comes before distribution.
   Every campaign should be connected to a target audience or segment before messages are sent.

5. Events and registration are campaign operations.
   Creating events, generating registration links, sending invitations, and tracking registration are in scope.

6. Survey and consensus should be connected.
   A campaign can launch or link a Survey & Consensus conversation to test messages, collect feedback, and measure sentiment.

7. Results should support decisions.
   Results should answer what happened, which audience responded, what message worked, what concerns emerged, and what should happen next.

## 3. Recommended Information Architecture

### 3.1 Main Campaigns Workspace

The Campaigns module should have these primary sections:

1. Brief
2. Messages
3. Audience
4. Events & Links
5. Updates
6. Results
7. Insights

The current task-oriented section should be removed or hidden from the Campaigns module. Existing task APIs can remain for now if other parts of the system rely on them, but they should not be presented as a primary campaign workflow.

### 3.2 Section Responsibilities

#### Brief
The campaign brief is the source of truth for strategy.

Fields:
- Campaign name
- Campaign type or category
- Problem statement
- Objective
- Target audience
- Geographic focus
- Core message
- Desired participant action
- Evidence or facts
- Risks and opposition arguments
- Campaign dates
- Owner or responsible team
- Visibility: public/private/internal

The brief should power message generation, campaign insights, public campaign pages, and Survey & Consensus statement suggestions.

#### Messages
A communication workspace for creating and managing campaign messages.

Message types:
- Short campaign message
- Long campaign message
- WhatsApp message
- Email message
- Social media post
- Talking points
- Press quote
- FAQ response
- Opposition response
- Event invitation
- Survey invitation
- Follow-up message

Message metadata:
- Message ID
- Campaign ID
- Audience segment ID
- Channel
- Tone
- Language
- Status: draft, approved, archived, sent
- Created by
- Created at
- Updated at
- Generated by AI: true/false
- Source prompt/context

Expected actions:
- Generate message variants
- Edit message
- Approve message
- Copy message
- Send/share message through available distribution channels
- Archive message

#### Audience
A section for selecting or creating the campaign audience.

Capabilities:
- Select saved segment from Network
- Show audience size
- Show available channels: email count, phone count, unknown contact count
- Show geography summary
- Show supporter/member mix
- Show missing data warnings
- Save audience as campaign target

This section should not duplicate the full People Directory. It should consume saved segments and show campaign-relevant audience readiness.

#### Events & Links
A campaign operations section for creating or selecting events and distributing campaign links.

Capabilities:
- Create event
- Select existing event
- Generate registration link
- Generate public campaign link
- Generate Survey & Consensus participation link when linked
- Send by email
- Open WhatsApp share
- Copy Slack-ready message
- Copy link
- Show QR code
- Track invite pipeline and registration status

This section is different from tasks. It is about participant-facing campaign actions.

#### Updates
A section for campaign updates that can be internal or public.

Update types:
- Public update
- Internal note
- Funding update
- Event update
- Result update
- Risk or issue update

Fields:
- Message
- Status: draft, published, internal
- Created by
- Created at
- Visibility

Public updates can appear on the public campaign page if visibility allows.

#### Results
A measurement section focused on campaign performance.

Metrics:
- Audience size
- Invitations sent
- Email sends and failures
- Link copies/shares if tracked
- Registrations
- Attendance, when available
- Survey participants
- Votes/comments/sentiment, when linked to Survey & Consensus
- Geographic response distribution
- Segment response rate
- Conversion rate
- Funding progress, if applicable

Results should be filterable by:
- Campaign
- Event
- Audience segment
- Channel
- Date range
- Geography

#### Insights
A strategic interpretation layer.

Examples:
- Strongest responding audience
- Weakest responding audience
- Most effective channel
- Main concern from comments
- Sentiment direction
- Recommended next communication
- Suggested follow-up audience
- Suggested message improvement

Insights should be generated from campaign data, audience data, event registration, and linked Survey & Consensus results.

## 4. Core User Flows

### 4.1 Create Campaign

1. Admin opens Campaigns.
2. Clicks Create campaign.
3. Completes campaign brief.
4. Saves campaign.
5. System opens campaign workspace.
6. Admin proceeds to Messages or Audience.

Required validations:
- Campaign name is required.
- Objective or problem statement should be strongly encouraged.
- Campaign status defaults to Planned.

### 4.2 Generate Campaign Messages

1. Admin selects a campaign.
2. Opens Messages.
3. Selects audience, channel, tone, and language.
4. Clicks Generate.
5. Backend sends campaign brief plus audience context to AI provider.
6. System returns message variants.
7. Admin edits and approves selected messages.
8. Approved messages become available in Events & Links distribution.

Generation inputs:
- Campaign brief
- Audience segment summary
- Channel
- Tone
- Desired action
- Language
- Optional admin instructions

Generation outputs:
- Message title
- Message body
- Call to action
- Suggested channel
- Suggested audience
- Risk notes

### 4.3 Select Campaign Audience

1. Admin opens Audience.
2. Selects saved segment.
3. System loads audience readiness summary.
4. Admin confirms audience for campaign.
5. Audience is attached to campaign.

Audience summary should include:
- Total people
- Email available
- Phone available
- Members/supporters mix
- Main cities/neighborhoods
- Data gaps

### 4.4 Send Event or Campaign Invitation

1. Admin opens Events & Links.
2. Selects campaign audience.
3. Selects or creates event, or selects campaign/survey link.
4. Selects approved message or writes custom message.
5. Chooses channel: email, WhatsApp, Slack/copy, QR.
6. Sends or copies.
7. System records invite/distribution metadata.

For email:
- Use direct backend email sending.
- Store send status.
- Store failures.

For WhatsApp:
- Open share URL with prepared message.
- Store share intent if possible.

For Slack/copy:
- Copy formatted message.
- Store copy action if possible.

### 4.5 Link Survey & Consensus

1. Admin opens Insights or Events & Links.
2. Clicks Create linked consultation.
3. System suggests statements based on campaign brief.
4. Admin edits statements.
5. Conversation is created in Survey & Consensus.
6. Participation link becomes available in Events & Links.
7. Results feed back into campaign Results and Insights.

### 4.6 Review Results

1. Admin opens Results.
2. Selects date range, event, channel, or segment.
3. Reviews reach, response, registrations, participation, comments, sentiment, and conversion.
4. Insights suggests next action.

## 5. Data Model

### 5.1 Existing Node Concepts

Current backend already uses or implies:
- Campaign
- CampaignContribution
- CampaignMilestone
- CampaignExpense
- CampaignProof
- CommunityPartner
- CampaignUpdate
- CampaignVolunteer
- Event
- Person
- Segment
- Conversation

### 5.2 Recommended New or Formalized Entities

#### CampaignMessage
Properties:
- messageId
- campaignId
- segmentId
- channel
- language
- tone
- title
- body
- callToAction
- status
- generatedByAi
- promptContext
- createdBy
- createdAt
- updatedAt

Relationships:
- (:Campaign)-[:HAS_MESSAGE]->(:CampaignMessage)
- (:CampaignMessage)-[:TARGETS_SEGMENT]->(:Segment)

#### CampaignAudience
This can be either a relationship or a node. A relationship may be enough.

Option A relationship:
- (:Campaign)-[:TARGETS {createdAt, createdBy, priority}]->(:Segment)

Option B node:
- (:Campaign)-[:HAS_AUDIENCE]->(:CampaignAudience)-[:USES_SEGMENT]->(:Segment)

Recommended: start with relationship unless multiple audience configurations per campaign are needed.

#### CampaignDistribution
Stores distribution attempts or share events.

Properties:
- distributionId
- campaignId
- messageId
- eventId
- conversationId
- segmentId
- channel
- audienceType
- recipientEmail
- recipientPhone
- sentCount
- failedCount
- status
- error
- link
- createdAt
- createdBy

Relationships:
- (:Campaign)-[:HAS_DISTRIBUTION]->(:CampaignDistribution)
- (:CampaignDistribution)-[:USES_MESSAGE]->(:CampaignMessage)
- (:CampaignDistribution)-[:TARGETS_SEGMENT]->(:Segment)

#### CampaignInsight
Optional if insights should be persisted.

Properties:
- insightId
- campaignId
- insightType
- title
- summary
- recommendation
- confidence
- source
- createdAt

Relationships:
- (:Campaign)-[:HAS_INSIGHT]->(:CampaignInsight)

## 6. Backend API Specification

Base prefix: `/crm`

### 6.1 Campaign Brief

Existing endpoints can continue:
- `GET /crm/campaigns`
- `POST /crm/campaigns`
- `GET /crm/campaigns/{campaignId}`
- `PATCH /crm/campaigns/{campaignId}`

Recommended additions or refinements:
- `GET /crm/campaigns/{campaignId}/brief`
- `PUT /crm/campaigns/{campaignId}/brief`

### 6.2 Campaign Messages

Add:
- `GET /crm/campaigns/{campaignId}/messages`
- `POST /crm/campaigns/{campaignId}/messages`
- `PATCH /crm/campaigns/{campaignId}/messages/{messageId}`
- `DELETE /crm/campaigns/{campaignId}/messages/{messageId}`
- `POST /crm/campaigns/{campaignId}/messages/generate`

Generate request:
```json
{
  "segmentId": "string",
  "channel": "email|whatsapp|social|talking_points|press|faq|opposition_response",
  "tone": "clear|urgent|hopeful|formal|community|mobilizing",
  "language": "ka|en",
  "instructions": "optional admin guidance"
}
```

Generate response:
```json
{
  "messages": [
    {
      "title": "string",
      "body": "string",
      "callToAction": "string",
      "channel": "string",
      "tone": "string",
      "language": "string",
      "riskNotes": "string"
    }
  ]
}
```

### 6.3 Campaign Audience

Add:
- `GET /crm/campaigns/{campaignId}/audience`
- `PUT /crm/campaigns/{campaignId}/audience`
- `GET /crm/campaigns/{campaignId}/audience/summary`

Audience summary response:
```json
{
  "segmentId": "string",
  "segmentName": "string",
  "totalPeople": 0,
  "emailAvailable": 0,
  "phoneAvailable": 0,
  "members": 0,
  "supporters": 0,
  "topCities": [],
  "dataGaps": []
}
```

### 6.4 Events & Links

Existing event endpoints can continue:
- `GET /crm/events`
- `POST /crm/events`
- `POST /crm/events/{eventId}/register`
- `POST /crm/events/{eventId}/register/bulk`
- `GET /crm/events/{eventId}/registrations`

Recommended campaign-aware endpoints:
- `POST /crm/campaigns/{campaignId}/events`
- `GET /crm/campaigns/{campaignId}/events`
- `POST /crm/campaigns/{campaignId}/distributions`
- `GET /crm/campaigns/{campaignId}/distributions`

Distribution request:
```json
{
  "messageId": "string",
  "segmentId": "string",
  "eventId": "string",
  "conversationId": "string",
  "channel": "email|whatsapp|slack|copy|qr",
  "audienceType": "individual|segment|everyone|registered|verified",
  "recipientEmail": "optional",
  "recipientPhone": "optional",
  "link": "string"
}
```

### 6.5 Linked Survey & Consensus

Add:
- `POST /crm/campaigns/{campaignId}/consultation/suggest-statements`
- `POST /crm/campaigns/{campaignId}/consultation/create`
- `GET /crm/campaigns/{campaignId}/consultation/results`

Suggested statements response:
```json
{
  "statements": [
    "Statement 1",
    "Statement 2",
    "Statement 3"
  ],
  "rationale": "string"
}
```

### 6.6 Results and Insights

Add:
- `GET /crm/campaigns/{campaignId}/results`
- `GET /crm/campaigns/{campaignId}/insights`
- `POST /crm/campaigns/{campaignId}/insights/generate`

Results should aggregate:
- Distribution metrics
- Event registration metrics
- Survey participation metrics
- Sentiment metrics
- Segment response metrics
- Geographic metrics
- Funding metrics if applicable

## 8. AI Requirements

### 8.1 Message Generation

The AI prompt should include:
- Campaign brief
- Audience summary
- Desired channel
- Tone
- Language
- Desired action
- Constraints: no unsupported claims, avoid manipulative language, be clear and civic-minded

### 8.2 Statement Suggestions

The AI prompt should generate Survey & Consensus statements that are:
- Clear
- Voteable by agree/disagree/pass
- Not leading
- Not duplicative
- Relevant to campaign objective

### 8.3 Insights Generation

The AI prompt should summarize:
- What is working
- What is not working
- Main audience response
- Main objections or concerns
- Recommended next message
- Recommended next audience

### 8.4 Safety and Governance

AI-generated content should always be editable and require human approval before sending. Store whether a message was AI-generated and the context used to generate it.

## 9. Permissions and Privacy

Recommended permissions:
- View campaigns
- Create/edit campaigns
- Approve messages
- Send distributions
- View results
- View donor/funding details
- Publish public updates

Privacy rules:
- Segment-level results should be aggregated.
- Personal recipient details should only be shown where operationally necessary.
- Public campaign pages should not expose private supporter/member data.
- Anonymous survey identities should stay anonymous.

## 10. Implementation Phases

### Phase 1: Restructure Existing Campaign UI

- Remove or hide task-oriented Campaigns section.
- Add section tabs: Brief, Messages, Audience, Events & Links, Updates, Results, Insights.
- Keep existing campaign CRUD and public page.
- Keep existing event and invite functionality.

### Phase 2: Campaign Messages

- Add CampaignMessage model and endpoints.
- Add message generation endpoint.
- Add message editor and approval flow.
- Add copy/share/send actions using existing distribution patterns.

### Phase 3: Audience Attachment

- Attach saved Network segments to campaigns.
- Add audience readiness summary.
- Use selected campaign audience in Events & Links.

### Phase 4: Survey & Consensus Integration

- Generate suggested statements from campaign brief.
- Create linked Survey & Consensus conversation.
- Pull participation, comment, sentiment, and consensus metrics into Results.

### Phase 5: Results and Insights

- Add campaign results aggregation endpoint.
- Add insights generation endpoint.
- Add performance dashboard by segment, channel, geography, event, and survey.

## 11. Out of Scope

The following should not be built inside Campaigns:
- Full task management
- Kanban boards
- Internal team workload planning
- General CRM people editing
- Full email marketing automation platform
- Payment processor complexity beyond current contribution support

These can be separate modules or future integrations.

## 12. Success Criteria

The Campaigns module is successful if an admin can:

1. Create a campaign brief.
2. Select a target audience.
3. Generate and approve campaign messages.
4. Create or select an event or participation link.
5. Send or share invitations through consistent channels.
6. Link a campaign to Survey & Consensus when public input is needed.
7. Review results by audience, channel, geography, and participation.
8. Receive useful recommendations for the next campaign action.

The module should feel like a campaign command center, not a database and not a task board.
